## Actual checks prepared

- Complete demo deck is built BEFORE the Carpet actor spawns on it, then the actual server clock is frozen/stepped. Each step must produce a measured gametime increase.
- Carpet use once looks at real floor buttons; an authoritative powered=true block observation must follow. No powered-block setblock is used as activation.
- The exact unchanged999-byte black_powder loot member is the only extracted chain fixture. AMMO_PROVENANCE.json pins the retained archive/member hash; no complete archive, factory, recipe or private path is included. Native inventory observations check genuine custom-data powder and iron consumed once, held-button debouncing, cooldown, empty-iron rejection and last-unit behavior.
- Actual marker trajectories must hit a registered anchor; a wall must stop them. The wall case requires a real +1shot counter, observed live velocity/position approaching the actual loaded solid wall before lifetime/site limits, actual shell removal and no target/hit change. A native clone/blocks comparison checks the reference fixture after the first shot.
- A non-op survival bystander cannot register as a target. Its raised fixture deck puts its body in the trajectory envelope; actual per-tick shell proximity must occur using the same0.9-center/0.95-radius envelope as the kernel's hit logic. Health must remain unchanged, then a separate deliberate1-point damage control must lower it. This prevents a trivial out-of-path safety pass.
- Registered skeleton/drowned living damage entry positives, unregistered skeleton/neutral cow/boat negatives, and moved-out registered marker/living boundary negatives exercise the actual entry functions. The boundary marker case starts its hit context inside while native selectors verify the nearby registered target is outside; this is a collision-path component case, not a fired boundary-shot claim.
- Command parse failures are hard errors. After normal/failed shutdown, full actual server logs are scanned for function parsing/global ERROR/FATAL/uncaught-server failures; any match prevents success.

Native checks are assertions to be exercised, not reported passes. If Minecraft syntax, path, setup, Carpet or expected trajectory differs, preserve the actual failure and fix from evidence; do not relax checks to manufacture acceptance.
